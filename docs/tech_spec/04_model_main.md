- 작성: 2026-11-25
- 상태: **초안** (사용자 승인 전)
- 근거: 대화 결정 2026-11-25(plan_review 6-1∼6-7), 노션 `[Vishamos-Character]`
- 범위: 모델이 **무엇을 내놓으면** Vishamos가 **어떻게 연결하는지**만 정한다. 캐릭터 디자인·모델링 방식(형태, 폴리곤, 텍스처, 뼈 개수, 어느 표정을 뼈로 할지)은 사용자가 정하며 이 문서에 적지 않는다.

항목 구분: `확정` 노션·외부 규약에 명확한 것 / `확정(사용자 답변)` 대화로 정한 것 / `해석` 모호한 부분을 보충한 것(승인 필요) / `보류` 해당 작업 때 정함 / `확인 필요` 결정이 필요한 것 / `AI 제안` 근거가 없는 것(승인 필요)

### 1a. 시선 (1e)

| # | 내용 | 구분 | 근거 |
|---|---|---|---|
| 1e-1 | 계산과 적용을 나눈다. `EyeGaze` 하나가 시선 2축을 만들고, 같은 캐릭터에 붙은 `EyeGazeDriver`(추상, `Apply(Vector2)`) 전부에 넘긴다. 적용 방식은 컴포넌트를 갈아 끼워 바꾼다(UV, 나중에 눈 뼈·블렌드셰이프). 여럿을 함께 붙여도 된다 | 확정(사용자 답변) | 2026-11-26 대화(교체 쉬운 방식) |
| 1e-2 | 시선 값: 두 눈 평균. 가로 = (오른쪽 보기 값 − 왼쪽 보기 값), 세로 = (Up − Down). 눈마다 In/Out이 반대 방향임에 유의. 좌우 부호는 저장값(거울) 기준이며 실행 화면에서 확인한다 | 확정(사용자 답변) | Face §4·§4a, 01 4.4h |
| 1e-3 | 스무딩은 `HumanoidCharacter`의 `poseSmoothTime`과 같은 시간 상수 보간(값은 `EyeGaze` 인스펙터) | AI 제안 | 머리 회전 3-6과 같은 방식 |
| 1e-4 | `eyeBlink` 두 눈 평균이 0.5를 넘으면 직전 시선을 유지한다(감는 동안 시선 값이 튐) | AI 제안 | ARKit 동작 |
| 1e-5 | Face 신호 없음: 0.5초 유지 후 0.5초에 걸쳐 가운데(0,0)로 | 확정(사용자 답변) | plan_review 3-5와 같은 규칙 |
| 1e-6 | UV 적용(`EyeGazeUvDriver`): 대상 Renderer, 머티리얼 슬롯, 속성 이름(기본 `_BaseMap`), 축별 최대 이동량(기본 0.15, 부호로 방향 뒤집기). 시작할 때 원래 Offset을 저장하고 그 기준으로 더한다. 머티리얼은 인스턴스(`Renderer.materials`)로 바꿔 에셋 원본을 건드리지 않는다. 텍스처 Wrap Mode는 Clamp, 가장자리는 흰색이어야 한다 | AI 제안 | 2026-11-26 대화. 툰 셰이더도 `_BaseMap` Tiling/Offset을 유지하면 그대로 쓴다(2c) |

- 1c·1d·1e는 한 모델에서 섞어 쓸 수 있다. 어느 표정을 어느 방식으로 할지는 모델이 정한다.
- Face 값의 왼쪽/오른쪽은 저장값 기준(거울, 캐릭터 기준)이다(명세 01 4.4h). 외눈처럼 한쪽만 쓰는 모델은 대응표에서 한쪽 값만 연결한다.
- 어떤 Face 값을 쓸지는 실측(Data-4)을 보고 모델 쪽에서 정한다. 측정값은 `inMin`·`inMax` 보정(plan_review 4-2)에도 쓴다.

## 3. 확인 방법

| 상황 | 기대 결과 | 근거 |
|---|---|---|
| 새 모델 프리팹으로 플레이 | 없는 연결 지점은 경고 한 줄씩, 에러 없이 동작 | §1 |
| 고개 돌리기 | Head 아래에 붙인 것이 함께 돎 | 1b |
| 표정 뼈 채널에 Face 값 0 / 1 (Char-4 후) | 쉬는 포즈 / Blender에서 기록한 포즈와 같음 | 1d |
| 시선 옮기기 (Char-3 후) | 동공이 같은 방향(화면 기준 거울)으로 움직이고, 눈을 감았다 떠도 튀지 않음. Face 끊기면 1초 안에 가운데로 | 1e, 1a |
| Unity·OBS·VishasBody 동시 실행 | **60fps**(측정값을 이 칸에 적음) | plan_review 6-7 |
