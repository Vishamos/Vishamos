| 1d | Unity에서 캐릭터 앞쪽이 **+Z**, 위가 +Y, 단위 미터. 키는 제한 없음. | 해석 | 코드는 캐릭터가 +Z를 보는 기준. 배치할 때 루트를 y 180° 돌려 카메라를 마주 보게 함. 팔·손은 점 사이 방향만 써서 체형·크기와 무관. 루트 이동만 미터 단위라 실제 사람과 크기가 크게 다르면 `rootScale`로 맞춤 |
| 1e | 뼈 이름은 자유(Humanoid 매핑으로 연결). 매핑되지 않는 추가 뼈(머리카락·치마·장식)는 있어도 된다. 흔들림은 SpringBone 같은 플러그인이 맡는다. | 확정(사용자 답변) | Unity Humanoid는 추가 뼈 허용. 흔들림은 플러그인(2026-11-24 논의) |

| 1g | 선택 뼈 **Jaw**: 크게 벌어지는 입에 쓴다(코드 미구현). 사람형은 블렌드셰이프로 충분하다. | 보류 | 메인 캐릭터의 "다이나믹한 입"에서 정함(04) |

## 3. 표정 (블렌드셰이프)

Unity-chan처럼 얼굴 부위별 메시(입·눈·속눈썹·눈썹)에 블렌드셰이프를 둔다. 블렌드셰이프 이름과 Face 값의 연결은 `FaceExpression` 대응표(인스펙터)에서 모델마다 바꾼다.

| # | 내용 | 구분 | 근거 |
|---|---|---|---|
| 3a | 표정은 블렌드셰이프로 만든다. 같은 이름의 블렌드셰이프가 여러 메시에 있으면(예: 눈과 속눈썹) 함께 움직인다. | 확정(사용자 답변) | 대화 결정. `FaceExpression`이 이름으로 모든 메시를 찾음 |
| 3b | **좌우가 있는 것은 좌우를 나눠 만든다**: 눈 감기 L/R, 눈썹 L/R, 입꼬리(웃음) L/R. 왼쪽/오른쪽은 **캐릭터 기준**. | 확정(사용자 답변) | 대화 "양쪽을 따로 움직일 수 있으면 좋겠다". Unity-chan은 양눈·양눈썹이 한 덩어리라 한쪽만 움직일 수 없었음(2026-11-24 확인) |
| 3c | 입 모음 **A·I·U·E·O** 5개를 만든다. uLipSync 음소와 1:1로 연결한다. | 확정(사용자 답변) | `FaceExpression` 모음 표, Char-2 |
| 3d | 이름은 **ARKit 이름**(`eyeBlinkLeft`, `mouthSmileRight`, `browInnerUp` 등, Face §4 표), 모음은 `A`·`I`·`U`·`E`·`O`. `FaceExpression` 기본값이 이 이름 그대로 1:1(범위 0∼1)이라 설정 없이 동작한다. 모델에 없는 이름은 건너뛰고(시작할 때 경고 한 줄), 다른 이름을 쓴 모델은 프리팹의 대응표를 고친다. | 확정(사용자 답변) | 2026-11-24 "기본값을 특정 모델에 맞추지 말고, 안 되면 안 되는 대로". Face 규약 §4 |
| 3e | 권장 최소 목록: 눈 감기 L/R, 눈 크게 뜨기 L/R, 눈썹 올림 L/R·내림 L/R·안쪽 올림, 입 모음 5, 웃음 L/R, 입 다묾. 나머지 ARKit 항목은 필요할 때 추가. | AI 제안 | 현재 `FaceExpression` 기본 대응표와 Unity-chan에서 확인한 범위 |
| 3f | 블렌드셰이프 100 = 최대 표정. 과하면 대응표의 `maxWeight`로 줄인다(모델을 다시 만들 필요 없음). | 해석 | `FaceExpression` |
