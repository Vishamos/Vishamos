## 2. Body 데이터 사용 (오늘 구현하며 정한 것 → 노션에 반영)
- **2-1. 스무딩 방식.** One Euro Filter(구현됨). 노션에 방식과 이유(떨림과 반응 속도를 함께 잡음)를 적는다.
- **2-2. 스무딩 값.** `minCutoff`, `beta`. 오늘 플레이 중에 조절한 값은 플레이를 멈추면 사라지므로, 정한 값을 노션에 적는다. 지금 코드 기본값은 `minCutoff` 1, `beta` 0.
- **2-3. 필터 시간 간격.** `dt` = Body `timestamp_ms` 차이(구현됨). 첫 패킷·재시작에는 필터를 초기화.
- **2-4. 점 표시 기준.** Body 규약 §3.1(2026-11-24 판)은 팔꿈치·손목(13∼16)의 visibility가 낮으면 프레임당 약 8cm씩 튀므로 직전 값 유지 또는 약하게 반영, 기준 0.6∼0.7을 권한다. 테스트 구현(`HumanoidCharacter`, `941f11b`): 기준 0.65(인스펙터 조절), 안 보이면 직전 회전 유지, 0.5초 넘게 안 보이면 쉬는 자세로 내림. 노션에 적을 것: 기준값, 켤 때/끌 때 기준을 나눌지(깜빡임 방지), 놓쳤을 때 팔 동작(4-1과 함께).
- **2-5. 쓸 점 목록.** 33점 중 실제로 쓰는 점(예: 코·귀 0·7·8, 어깨·팔꿈치·손목 11∼16). 다리(25∼32)·골반은 앉은 자세에서 추측값이라 쓰지 않는 것을 추천(Body 프로토콜 §3.1). 프로토콜은 바꾸지 않고 Vishamos가 고른다(2026-11-22 논의).
- **2-6. 화면 배치.** 좌표 기준(캐릭터 루트의 `localPosition`), 캐릭터가 카메라를 보게 할 회전(y 180°), 거울 여부는 **결정됨(2026-11-23, 사용자): 항상 미러**, Vishamos가 수신할 때 적용(명세 01 4.3i). 노션에 적을 것.
- **2-7. 손 데이터 사용 시기.** 지금은 몸 33점만 쓴다. 손 21점을 쓸 단계가 되면, 같은 손 값이 반복된 패킷은 필터에 넣지 않는 규칙을 따른다(Body 프로토콜 §3.2, 이슈 VishasBody#1).
- **2-8. 손 제스처 (후순위).** 손 21점으로 손 모양(예: 주먹, 편 손, 브이, 엄지 척, 가리키기)을 판별해 쓸지. 쓰는 곳: 손 그림 교체(2D) 또는 표정·효과 실행. 정할 것: 제스처 목록, 각각 무엇을 실행하나, 오인식 방지(예: 0.3초 이상 유지해야 인정). 0-2(캐릭터 형태)와 머리·몸·얼굴이 끝난 뒤에 정한다(2026-11-23 논의).
- **2-9. 루트 위치 원점(기준점).** Body v2 루트 위치(카메라 기준 골반 위치)를 캐릭터 이동에 쓸 때 어디를 원점으로 할지. 정할 것: 언제 잡나(시작 시 첫 값 / 단축키 / 둘 다), 재시작·놓침 때 다시 잡나, 저장해 두나, 이동 배율. Body 규약 §3.3. **결정됨(2026-11-23, 사용자): 시작 후 첫 유효 값으로 자동, 다시 잡기는 단축키(Input System 패키지 설치 후. 그 전에는 인스펙터 메뉴 `Recenter`), 놓침·재시작 때 유지, 저장 안 함(Face 정면 보정 3-4 때 함께 정함), 축별 배율 `rootScale`(기본 1).** **추가 결정(2026-11-24, 사용자): 루트 이동은 기본 고정(xyz 전체, 배치한 자리), F10으로 풀고 다시 고정.** 풀었을 때 흔들림은 데드존 0.1m + 0.3초 따라가기(테스트 값). 테스트 구현: `HumanoidCharacter`. 노션에 적을 것.
- **2-10. 본별 최대 각도 (후순위).** 웹캠 깊이 오차로 팔꿈치가 반대로 꺾이거나 고개가 과하게 도는 것처럼, 정상 값이지만 캐릭터에게 과한 자세를 막을지. 수신(명세 01)이 아니라 캐릭터 적용 단계(Doc-3)에서 캐릭터마다 설정한다. 지금 `HumanoidCharacter`는 Transform에 직접 회전을 넣어서 Avatar Muscle 한계가 걸리지 않으므로, 하려면 쉬는 자세 기준 각도를 직접 자르는 방식을 추천한다. 실제로 문제가 보일 때 정한다(2026-11-23 논의).

## 3. 머리 회전 (2026-11-22 논의, 새 기획)
웹캠(Body)으로 계산한 고개 각도는 실제의 약 절반(90° → 약 45°)이다. 단일 카메라의 깊이(z) 추정 한계라 보정으로 해결되지 않는다.

- **3-1. 역할 분담.** 머리 **회전**은 Face iOS(ARKit 얼굴 자세), 머리·목 **위치**는 Body(코 또는 양 어깨 중점). 이 분담을 Vishamos 노션에 적는다.
- **3-2. VishaFace_IOS 기획 변경 (노션 VishaFace_IOS 페이지).** 지금 Face 사양 §3.3에 "머리 회전·위치는 보내지 않는다"로 결정되어 있다. 이를 바꿔 머리 회전(쿼터니언)을 보내도록 적는다. 위치(3값)도 보낼지 정한다(추천: 회전만. 위치는 Body가 맡음).
- **3-3. 좌표계를 누가 바꾸나.** 추천: **Face 앱이 Unity 좌표로 바꿔서 보낸다**(Body와 같은 방식). 회전의 기준(캐릭터 기준 정면/위)과 거울 여부를 2-6과 같게 맞춘다.
- **3-4. 정면 보정(리센터).** 폰과 모니터 정면은 각도가 다르다(예: 눈높이보다 15cm 위, 60cm 거리면 약 14° 아래를 보는 것으로 읽힘). 그래서 "모니터를 볼 때를 정면으로" 맞추는 보정은 필요하다. 정할 것: 어디서 실행하나, 저장해 두나 매번 하나. 추천: 폰이 암·모니터에 고정이므로 **설치 때 한 번(거치대를 옮겼을 때만 다시) 실행하고 설정 파일에 저장**한다. 실행은 Vishamos 단축키로 충분하고, 방송마다 누를 필요가 없으므로 이 기능 때문에 VishasController를 앞당길 필요는 없다(2026-11-23 논의).
- **3-5. 추적이 끊길 때.** 많이 돌려 얼굴이 안 보이면 Face flags가 0이 되고 마지막 값이 온다(Face 프로토콜 §5). 그동안 머리를 마지막 각도로 둘지, 정면으로 천천히 돌릴지 정한다. 실제로 몇 도에서 끊기는지는 측정 필요(Face 사양 §3.6).
- **3-6. 회전 스무딩.** 추천: 앞 방향·위 방향 벡터에 One Euro를 걸고 `LookRotation`으로 다시 만든다. 값은 2-2처럼 테스트 후 적는다.

## 4. 이전부터 남은 결정 (노션 "다음 단계" 절)
- **4-1. 놓침·신호 없음일 때 캐릭터 동작.** 마지막 자세 유지 / 기본 자세로 복귀(복귀까지 몇 초).
- **4-2. 블렌드셰이프 보정.** 사람마다 최대치가 1에 못 미치고 무표정에도 값이 있음(Face 프로토콜 §5). 배율·기준값 보정을 할지, 어떻게 맞출지.
